# Тест-дизайн ядра: авторизация и управление картами

Источники: [ТЗ авторизации](../../tz/04-authorization.md), [ТЗ управления картами](../../tz/05-card-management.md), [описание интерфейсов](../api-spec.md). Это проект проверок, не результаты. Суммы указаны в копейках. Исходные данные **Б**: активная карта с будущим сроком, известным BIN и запасом по лимитам и балансу. `POST` означает покупку через `/api/transactions` с корректными остальными полями. Для каждой проверки нужна новая карта или сброс состояния.

Требования: A1 карта, A2 статус, A3 срок, A4 дневной лимит, A5 месячный лимит, A6 баланс, A7 резервирование, A8 ошибка сервиса карт, A9 RRN и authCode. Это пункты §2–6 ТЗ авторизации. C1 создание, C2 операции с картой и список, C3 генератор, C4 Лун, C5 резервирование. Это пункты §2–5 ТЗ управления картами. `+` означает позитивную проверку, `−` означает негативную. Если код ответа не задан ТЗ, проверяется факт отказа без выдуманного кода.

## 1. Классы эквивалентности

| Поле | Классы и представители | Ожидание |
|---|---|---|
| Карта | Есть, нет | Проверка далее, отказ `14` |
| Статус | ACTIVE, INACTIVE, BLOCKED, EXPIRED | Допуск, отказ с причиной статуса, для EXPIRED код `54` |
| Срок | `1026`, `0926`, `0826` при дате 24.09.2026 | Допуск, допуск по уточняемому правилу, отказ `54` |
| Сумма к дневному и месячному остатку | Ниже, равна, выше на 1 | Первые два допустимы, превышение даёт отказ |
| Сумма к балансу | Ниже, равна, выше на 1 | Первые два допустимы, превышение даёт `51` |
| Сервис карт | Доступен, недоступен | Обычное решение, отказ `05` |
| BIN и PAN | 6-значный BIN и PAN по Луну, неверная длина, нецифровой ввод, неверный Лун | Карта создаётся только из корректных данных |
| Генератор | `count=100` и пять BIN, пустой список, нулевой count | 100 карт, для невалидных входов карты не создаются |
| `MMYY` | `0926`, `0026`, `1326`, `092`, `09260`, `AA26` | Только корректный формат и месяц допустимы |

Некорректные классы проверяются по одному на проверку. Исключение составляют A-20 и A-21, где два нарушения нужны для проверки порядка отказов. Произвольный срок карты нельзя передать через публичный интерфейс, поэтому формат `MMYY` проверяется на уровне компонента.

## 2. Граничные значения

Для каждой границы взято значение на ней и по одному значению с каждой стороны.

| Поле и состояние | Ниже | На границе | Выше | Проверки |
|---|---|---|---|---|
| Дневной остаток `60000` | `59999` допуск | `60000` допуск | `60001` отказ `61` | A-09–A-11 |
| Месячный остаток `60000` | `59999` допуск | `60000` допуск | `60001` отказ | A-12–A-14 |
| Баланс `10000` | `9999` допуск | `10000` допуск | `10001` отказ `51` | A-15–A-17 |
| Срок при дате 24.09.2026 | `0826` отказ `54` | `0926` допуск* | `1026` допуск | A-06–A-08 |
| Длина PAN | 15 не найден | 16 корректно | 17 не найден | C-01, C-09, C-10 |
| Месяц `MMYY` | `00` невалиден | `01` и `12` валидны | `13` невалиден | C-12a, C-12b |
| Длина `MMYY` | `092` невалидно | `0926` валидно | `09260` невалидно | C-13a, C-13b |

*Для текущего месяца принято допущение о действии карты до конца месяца. ТЗ не уточняет день истечения и источник времени, поэтому A-07 нельзя оценивать до согласования правила. Контрольная цифра PAN проверяется отдельно в C-01 и C-11.

## 3. Попарное тестирование

[Модель PICT](pict/model.txt) содержит семь параметров и ограничения. [Набор](pict/cases.txt) содержит 25 строк и покрывает все 186 допустимых пар. Полный перебор дал бы 2592 сочетания, после ограничений допустимы 504. Каждая строка набора соответствует одной проверке PW ниже. Попарное тестирование не заменяет проверки порядка A-20 и A-21.

Для PW сумма равна `10000`. Значения `under`, `at`, `over` в модели означают остаток лимита или баланс `10001`, `10000`, `9999`. Счётчики расхода и карта задаются отдельно для каждой строки. Значение `future` означает следующий месяц, `past` означает предыдущий. В шаге `POST Rn` используются также поля `terminalType` и `mcc` из строки n. После отказа баланс и расход остаются прежними.

[Модель управления картами](pict/model-card-management.txt) содержит шесть параметров и ограничение. [Набор](pict/cases-card-management.txt) содержит 15 строк и покрывает все 118 допустимых пар. Он проверяет фильтры и пагинацию списка карт. Для набора `mixed` подготовлены пять карт: две ACTIVE и одна BLOCKED с BIN 400000, одна ACTIVE и одна INACTIVE с BIN 500000. Значение `one` добавляет шестую карту со статусом DELETED и BIN 500000. Набор `empty` не содержит карт. Удалённая карта никогда не попадает в список. Значение `all` означает отсутствие соответствующего фильтра.
